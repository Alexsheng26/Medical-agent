# Proposal：面向临床–转化医学研究的个性化科研中间体系统

**Personal Research Intermediary Agent for Translational Medicine Scientists**

> 本文是本仓库的立项方案书。每个条款后标注实现状态：
> **[已实现]** / **[部分实现]** / **[需人工]**（软件层面无法承诺，说明原因）。

---

## 一、项目总览

构建一个以医学科学家为中心、长期演化的科研中间体。它不是通用聊天机器人，
而是围绕研究者个人的课题方向、数据基础、目标期刊与写作风格持续学习的智能协作系统，
覆盖 **文献调研 → 假说打磨 → 数据评估 → 期刊风格写作 → 母语化与去 AI 化** 的全链条。

设计原则：**科学判断权归研究者**。系统承担劳动、守住证据边界，并在最容易自欺的环节
（新颖性判断、过度声称、伪造引用）主动制造摩擦。

---

## 二、建设目标

### 目标 1｜文献驱动的假说生成与迭代 **[已实现]**

- 根据给定主题/临床问题自动检索文献 → `mra search`
- 结构化总结与提炼 → `mra digest`
- 多轮 NLP 对话共同澄清问题、识别 gap、迭代假说 → `mra chat`
- 输出具备创新性和逻辑完整性的 Proposal 框架 → `mra proposal`

### 目标 2｜专业期刊风格内化 **[部分实现]**

- 学习并内化文章结构、句式文法、叙事逻辑、图表–故事耦合 → `mra journal add`
- 输出可复用的期刊风格模板 → `mra journal show`

*限制：仅用 PubMed 摘要建档时，只能支撑标题与摘要层面的判断；结构性结论需加全文样本。*

### 目标 3｜基于基础数据的期刊适配评估与写作 **[已实现]**

- 接收基础实验/临床数据 → `mra assess`
- 创新性 / 机制深度 / 数据充分性评估 → 五维打分 + 短板诊断 + 补实验建议
- 按目标期刊风格生成初稿 / Native 化稿 / 去 AI 化终稿 → `mra draft`、`mra finalize`

### 目标 4｜长期演化与课题凝练 **[已实现]**

- 沉淀核心科学问题、归纳稳定研究方向 → `mra memory`（概念频次 + 共现图 + 假说轨迹）
- 形成个人写作指纹 → `mra fingerprint`
- 跨项目逻辑一致性校验 → `mra diff`（假说版本逐字段比较）

## 三、系统功能条款

### Clause 1｜文献检索与知识提炼

| 条款 | 内容 | 状态 |
|---|---|---|
| 1.1 | 支持 PubMed 检索 | **[已实现]** E-utilities，含限速与重试 |
| 1.2 | 按关键词、MeSH、临床问题、机制通路组合检索 | **[已实现]** 模型规划检索式，支持三轴结构与基因别名；亦可直接传入自写检索式 |
| 1.3 | 自动提取科学问题 / 核心发现 / 研究方法 / 创新性声明 / 局限性 | **[已实现]** 结构化输出，额外提取机制关键词、临床相关性、1–5 级证据强度 |
| 1.4 | 输出结构化文献摘要与证据图谱 | **[已实现]** 摘要见 `digest`；图谱见 `memory --refresh` |

> **Embase / Scopus / Web of Science 未实现。** 三者均需机构订阅与付费 API 授权，
> 无法在开源仓库中提供可用实现。`mra export` 提供了导入外部检索结果的数据通路。

### Clause 2｜NLP 科学对话与假说迭代

| 条款 | 内容 | 状态 |
|---|---|---|
| 2.1 | 多轮、上下文连续的科研对话 | **[已实现]** 对话历史持久化于知识库 |
| 2.2 | Socratic 提问 / 机制链完整性检查 / 对照与阴性结果分析 / 创新性层级判断 | **[已实现]** 见 `prompts/dialogue.md`、`prompts/hypothesis.md` |
| 2.3 | 所有引用与事实必须来源于已索引文献库 | **[已实现]** 见 QA-1 |
| 2.4 | 假说版本管理与比较 | **[已实现]** append-only 存储 + `mra diff` |

机制链要求**每一步单独可测**，尚未被实证的步骤必须单列——薄弱环节因此可见。
假说冻结时强制填写反证文献与最可能失败之处。

### Clause 5｜Native 化与去 AI 化写作

| 条款 | 内容 | 状态 |
|---|---|---|
| 5.1 | Native 化：领域惯用表达、句式多样性、期刊修辞习惯 | **[已实现]** 专门针对中文母语者干扰模式 |

## 四、系统架构

```
├── 命令行界面 (mra)
│
├── 文献情报层
│   ├── PubMed E-utilities 客户端       pubmed.py
│   ├── 元数据解析（纯函数，可离线测试） pubmed.py
│   └── SQLite 知识库 + FTS5/BM25        store.py
│
├── 科学对话引擎
│   ├── 上下文记忆（持久化对话）         store.py
│   ├── 假说追踪（append-only 版本化）   dialogue.py
│   └── 批判性思维模块                   prompts/dialogue.md
│
├── 期刊风格建模
│   ├── 风格提取器                       journal.py
│   ├── 体裁模板                         schemas.py
│   └── 修辞规则                         prompts/journal_profile.md
│
├── 数据–故事评估器
│   ├── 数据解析（CSV/TSV/文本）         assess.py
│   ├── 五维评分模型                     schemas.py
│   └── 短板分析                         prompts/evaluate.md
│
├── 母语化与去 AI 化单元
│   ├── 初稿生成                         writing.py
│   ├── 母语化规则                       prompts/nativize.md
│   └── 去 AI 化检测 + 迭代改写           deai.py / writing.py
│
└── 个人演化层
    ├── 课题方向图谱                     memory.py
    ├── 写作指纹                         memory.py
    └── 长期记忆                         store.py / memory.json
```

**检索为什么用 BM25 而不是向量检索：** SQLite FTS5 的 BM25 不需要 embedding 模型、
不需要向量数据库、不需要额外联网服务。整个知识库是一个可备份的单文件，
完全满足 QA-3 的本地化要求。代价是同义改写的召回弱于语义检索——
这一点由检索式规划阶段（模型主动展开 MeSH 与基因别名）补偿。

## 五、质量控制条款

| 编号 | 条款 | 实现方式 |
|---|---|---|
| **QA-1** | 参考文献真实性：严禁虚构，所有引用必须可追溯至知识库 | **[已实现]** 强制 `[PMID:x]` 格式；`mra refs` 逐条核验，发现伪造返回退出码 1；无法支撑的论断标记 `[CITATION NEEDED]` |
| **QA-2** | 科学责任归属：输出仅作辅助，科学判断与发表责任由研究者承担 | **[需人工]** 已写入核心提示词并在文档中声明 |
| **QA-3** | 数据隐私：原始数据不出本地 | **[已实现]** SQLite 单文件 + 本地 Markdown；检索无需外部服务；`.gitignore` 已排除工作区与数据目录 |
| **QA-4** | 去 AI 化合规：投稿前必须经过人工母语化改写与专业润色 | **[需人工]** 工具产出 v2 与报告，人工通读不可省 |
| **QA-5** | 持续评估：定期评估科学性、风格一致性与 AI 痕迹水平 | **[部分实现]** AI 痕迹可量化追踪（`mra lint`）；科学性与风格一致性需人工盲评 |

## 七、验收标准

| 标准 | 可否由软件保证 | 说明 |
|---|---|---|
| 自动生成符合顶刊结构的 proposal 框架 | ✅ 可 | `mra proposal` |
| 引用零虚构 | ✅ 可 | QA-1，`mra refs` 可作为提交前脚本卡口 |
| 假说版本可追溯、可比较 | ✅ 可 | `mra diff` |
| AI 痕迹可量化并持续下降 | ✅ 可 | `mra lint` 分数可追踪 |
| 新课题启动效率提升 ≥ 30% | ⚠️ 需实测 | 依赖使用习惯，需连续使用后自行评估 |
| **期刊风格相似度 > 80%（人工盲评）** | ❌ 不可 | 相似度必须由人判断，代码给不出这个数字 |
| **AI 检测工具得分 < 15%（GPTZero / Turnitin）** | ❌ 不可 | 见下 |
| 研究者主观满意度 ≥ 4.5/5 | ❌ 不可 | 主观指标 |

> ### 关于"AI 检测得分 < 15%"
>
> 这一条无法承诺，原因是技术性的：GPTZero、Turnitin AI 等检测器是基于 token 似然的
> **统计分类器**，闭源、持续更新、且无法从外部复现。任何声称能保证特定检测分数的工具
> 都是在承诺它控制不了的东西。
>
> `mra lint` 做的是另一件事：检测让文本读起来像机器写的**表层习惯**——固定套话、
> 句长方差过低、段落长度均匀、连接词开头密度、名词化密度。分数低意味着这些痕迹
> 已经消除，**不等于对任何商业检测器的预测**。
>
> 这个说明同时写在 `mra/deai.py` 的文档字符串里和每一次 `mra lint` 的输出中，
> 以免使用者在关键时刻误判。

## 八、下一步

1. 用你当前的研究方向跑通一次完整 Demo：`mra search` → `chat` → `hypothesis` → `proposal`
2. 准备 3 本目标期刊各 3–5 篇全文样本，建立可用于分节写作的风格档案
3. 用你自己已发表的论文建立写作指纹：`mra fingerprint ./my_papers`
4. 按需要修改 `mra/prompts/` 下的提示词——追问强度、评估严格度、去 AI 化力度都在那里
